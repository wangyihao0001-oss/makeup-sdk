本次交付需求补充、可交互视觉原型和 Stitch 设计稿，不包含实时摄像头、人脸追踪、妆效渲染、小程序客户端或后端实现。原型里的「开启相机」「拍下」仅切换设计状态，照片始终为静态示例；切换颜色和款式不会重新计算照片中的妆效。按住对比仅演示按下和释放状态，不提供真实前后对照。相册保存明确提示尚未接入，不伪装保存成功。

## 入口与范围

主导航为广场、试衣、试妆、我的。P01/P02/M01/P09 共用四项导航；P09 的我的记录新增「私人试妆」。试衣页面继续使用中性色，只有试妆控制区和选中状态使用淡粉。

首版设计覆盖口红、睫毛、眼线、眼影、腮红、底妆，重点细化口红和睫毛。支持多个部位叠加、单类移除、清除全部、原妆对比、拍摄结果、继续调整及私人记录管理。不加入脸型调整、自动美颜、商品功效承诺、自动公开或自动上传。

## 页面与路径

- M01 试妆入口：自然肤色示例图、六类入口、相机使用说明、开启相机和我的试妆。正式实现只在主动点击后请求相机权限。
- M02 试妆镜 · 口红：固定人像框、摄像头切换、按住对比、清除全部、快门；下方显示六类标签、色块、当前色号、单类「无」及质感分段控件。
- M03 试妆镜 · 睫毛：与 M02 共用同一布局，显示款式和黑/棕色色块，不显示质感控件。款式缩略图目前复用同一眼部照片，最终款式名称和纹理须按实际 SDK 素材确认。
- M04 试妆结果：私人照片、冻结的妆容配置清单、保存私人记录、继续调整、相册保存入口。没有公开按钮或自动分享。
- M05 私人试妆记录：缩略图行、妆容信息、时间、查看、删除与空态。列表中的初始两条是演示数据。
- S03 异常与空态：MU01—MU10 展示权限拒绝、无人脸、多人、遮挡/光线不足、素材加载失败、设备不支持、保存失败、空态、后台暂停和删除确认。

主路径：M01 → M02/M03 → M04 → 保存 → M05。继续调整从 M04 返回编辑器并恢复拍摄时的配置；查看已保存记录不会覆盖正在编辑的配置，只有主动继续调整才恢复该记录。

## 视觉与切换

局部 token：控制区 #FFF7FA，选中背景 #FCE7EF，强调文字 #A62B58，边线 #F0DFE6；画面边界 #FFFFFF，主操作沿用 #FF385C。照片无 CSS 色彩滤镜，也不叠淡粉遮罩。口红、眼影等真实色块独立于主题色。

试妆镜使用固定网格：56px 顶栏、可伸缩人像区（至少 220px）、76px 拍摄行、270px 控制区、44px 提示。控制区内部滚动，分类切换不移动脸部和快门。小于 720px 的视口允许页面纵向滚动。正式小程序实现需要额外计算系统状态栏与安全区。

类别切换使用 180ms 的颜色过渡，不卸载相机或重启追踪；减少动态效果偏好下关闭过渡。按住对比不修改配置，手指释放、取消、失去焦点、切后台都恢复。选中态同时使用描边、勾或底线，不能只靠颜色。图标按钮有可访问名称和悬停说明；分类支持方向键切换。

## 数据和隐私边界

正式实现中，实时帧和人脸关键点只用于当前会话，不默认落库、不进入日志或分析事件。权限弹窗前不初始化摄像头。离开编辑器、切后台或销毁页面时停止相机并释放资源；重新进入时恢复妆容参数，重新确认权限和追踪可用状态。

「拍下」产生当前帧及妆容参数的结果快照；只有「保存到我的试妆」才创建私人记录，重复点击不重复创建。返回调整不改写旧记录，新拍摄另建快照。正式私人保存使用已有按需登录、服务端所有权检查和私人图片授权机制；不能把前端隐藏当作访问控制。

原型仅把示例记录与参数保存在当前浏览器 localStorage，不保存用户摄像头数据、不执行网络上传，不具备服务端隐私保障。删除只移除本机原型记录；保存结果不代表真实照片上传。清空浏览器存储会丢失本机演示记录。

无人脸、多人、遮挡或光线不足时，正式拍摄必须禁用。加载某个妆效失败时保留其他妆效；保存失败时保留当前结果并允许重试。设备不支持时不自动改用云端上传。导出到相册的副本不随私人记录删除而撤回。

## OpenMakeupSDK 对应关系与适配门槛

参考：[仓库与说明](https://github.com/ehsanwwe/OpenMakeupSDK)、[实际 API 源码](https://github.com/ehsanwwe/OpenMakeupSDK/blob/main/src/OpenMakeup.js)、[类型声明](https://github.com/ehsanwwe/OpenMakeupSDK/blob/main/src/index.d.ts)、[许可文件](https://github.com/ehsanwwe/OpenMakeupSDK/blob/main/LICENSE)。本项目已固定上游提交 `12c5a8023aab0fcec7eef4fbdc0d1a29cf9989dd`，并在阿里云完成 SDK/WASM/binding 回归；真机视觉和性能仍待补录。

- 六类映射为 lipstick / mascara / eyeline / eyeshadow / blush / foundation。眼线规范键是 `eyeline`；不要仅照 README 的英文名称拼接调用。
- `apply(category,{color,pattern,finish})` 对应上色和款式；单类清除用 `clear(category)`，全部清除用 `clearAll()`。
- 质感只应用于口红、眼影、腮红、底妆；睫毛、眼线不显示质感控制。具体质感效果和支持程度仍需样本实测。
- `getPatterns(category)` 的实际返回值决定款式选项，不能把设计中的自然/纤长等示例名称当成 SDK 已有商品目录。参数保存使用纹理稳定 ID、版本和颜色，不使用展示排序充当稳定标识。
- 已检查的公开 `apply` 接口没有独立的妆效浓度参数，因此本次不设计浓度滑杆。截图、前后对比、摄像头切换、保存和产品记录由接入层实现，不能宣称 SDK 已直接提供整套业务能力。
- 上游浏览器实现依赖 HTMLVideoElement、HTMLCanvasElement、MediaPipe 与 Three.js；本项目已用无 Three.js WebGL、内置 FaceMesh 资源和微信宿主适配器替换这些依赖。H5 仍不能替代小程序真机验证。
- 接入前锁定版本与依赖、审查纹理资源及第三方许可、部署可控静态资源；验证微信基础库和真机环境的权限恢复、横竖屏、前后摄像头、内存、掉帧、追踪稳定和退出释放。不要在未验证时默认以 web-view 作为可用方案。

## 设计验收

本地原型检查脚本为 `scripts/verify-preview.cjs`：22 页、44 次宽度组合检查，包含 320px/390px 移动布局与 1200px 状态板；图片加载和横向溢出检查。检查类别切换前后人像框位置相同、口红色号与质感保留、睫毛不出现质感、键盘对比状态恢复、结果快照、继续调整、保存去重、删除与空态。它不验证真实人脸跟踪、妆效准确度、实时性能或小程序权限。

Stitch 是否已实际挂载和完成远端视觉检查，以 `stitch-sync-v3.2.json` 为准，不以生成工具返回的文案作为验收结论。
