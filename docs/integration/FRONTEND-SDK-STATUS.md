# 业务前端与 SDK 接入状态

来源：`dress/docs/FRONTEND.md` 第 5 节及 `dress/研发分工/前端研发执行文档.md`。迁移日期：2026-10-23。

## 当前业务流程

业务侧已有 M01 六类入口 → M02/M03 镜面 → M04 快照 → 按需登录保存 → M05 私人记录的流程。后台/离开释放、冻结参数和 `saveRequestId` 去重已有实现；保存重试复用已完成上传和请求 ID，并检查所属账号。

## 当前 mock 边界

- `MockMakeupEngine.apply()` 不渲染妆效，纹样目录为合成数据；unsupported 不初始化相机、不转云端。
- H5 mock 会申请相机流，小程序 mock 包含相机授权/组件路径，但没有把真实帧接入追踪和渲染。
- 人脸状态来自开发测试状态，默认 ready；没有实际检测无人脸、多人或光照。测试只验证状态处理逻辑。
- `capture()` 返回静态示例图，并非当前相机帧或 WebGL 成图；对比及镜头切换没有真实效果。
- 示例快照和参数留在会话内存，主动保存才上传 `private_makeup_result`；列表、详情、删除调用业务 API。该流程用于业务联调，不能验收 AR 能力。

## 接入待办

1. 锁定 SDK 提交、依赖、模型/纹样清单和资源版本，明确静态资源域名与缓存策略。
2. 在 Android、iOS 和微信小程序验证相机帧 → 人脸关键点 → 平台 GPU 合成 → 当前帧导出。
3. 将产品 `dewy` 映射到 SDK `glossy`，所有类别使用稳定纹样 ID，不以展示排序作为标识。
4. 将异步资源加载、连续切换竞态、拍摄等待和失败恢复纳入统一状态模型。
5. 记录镜像坐标、颜色空间、输出方向、镜头切换、资源释放和三端性能结果。

上游 OpenMakeupSDK 核对日期为 2026-10-22；正式复用前仍需固定提交、审查许可证和资源来源。第一验收门槛是三端真实设备上的单类口红闭环，静态图和 H5 演示不能替代真机证据。
